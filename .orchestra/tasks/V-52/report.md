# V-52 — выравнивание документов, обзорные листы, смена модели

Готово к приёмке оркестратором; реальных фотографий и доступа к проду в копии нет.
CHANGELOG: **v2.14.0**, дефолты моделей не менялись.

## Реализация

- `tools/orient_photo.py`: один/несколько файлов, JSONL в stdout, неизменяемые
  исходники, приватные PNG-копии (0600), уникальные имена в `/tmp/kesha/oriented/`
  или `--output-dir`. EXIF применяется перед анализом; угол означает коррекцию
  PIL против часовой стрелки после EXIF. Ориентация анализируется в grayscale,
  результат сохраняется в RGB. Распознанный текст не выводится.
- `--sheet`: сначала выравнивание, потом листы; `--sheet-only`: листы из уже
  готовых копий без OCR. До четырёх фото на лист, порядок входов сохранён,
  глобальные номера ячеек и stdout-соответствие номер → исходник/полноразмерная
  копия. Невалидный файл не сдвигает номера оставшихся. `--cell-size 780`
  по умолчанию, допустимо 256–780; исходники меньшего размера не растягиваются.
  У миниатюры длинная сторона до 780 px, отступы по 2 px, сторона листа ≤1568 px.
- Промпт обоих рантаймов: документы перед чтением выравнивать; несколько фото
  сначала смотреть на листах, мелкий текст и ВСЕ реквизиты — только на нужной
  полноразмерной копии. Непонятные данные не угадывать. Это инструкция агенту,
  не новый автоматический фильтр входящих сообщений.
- Pillow и `rapid-orientation==0.0.11` добавлены в requirements. Последний
  транзитивно устанавливает ONNX Runtime, OpenCV, NumPy, PyYAML; его metadata
  требует Python <3.13. README ru/en теперь явно указывает Python 3.12 и
  системные пакеты Tesseract rus/eng.
- Промпт разрешает смену `CLAUDE_MODEL` / `KESHA_CODEX_MODEL` по просьбе владельца
  в `.env` развёрнутого бота, сохранение приватных прав, уведомление перед
  рестартом и проверку модели после него. Названий моделей в промпте нет.
- Оба пути рестарта берут `BOT_SERVICE_UNIT = "kesha-bot-vps"` из `config.py`.
  Устранён соответствующий пункт строки V-46 в TODO, инструкции service в
  README согласованы с этой константой.
- Sonnet 5.5 добавлен в таблицу ожидаемых 128000 output tokens; `[1m]`
  поддерживается существующим общим резолвером без удвоения суффикса.

## Уверенность и отказ от поворота (после приёмки на реальных фото)

Первая версия (OCR без увеличения, порог ≥20 / отрыв ≥10 и ×1.5) определила 3 из
12 документов: на остальных tesseract молчал или давал баллы 3–29. Ошибок не было.
Правило пересмотрено по агрегатам приёмки (балл, сильных слов) на четырёх углах
после grayscale-увеличения 2× LANCZOS:

|---|---|---|---|---|---|---|
| 1 | 0,0 | 161,23 | 0,0 | 9,2 | 90 | 90 ✔ |
| 2 | 3,1 | 0,0 | 3,1 | 0,0 | 0 | оригинал ✔ |
| 3 | 3,1 | 1276,6 | 0,0 | 0,0 | 90 | 90 ✔ |
| 4 | 0,0 | 19,3 | 0,0 | 0,0 | 90 | 90 ✔ |
| 5 | 0,0 | 5,1 | 0,0 | 0,0 | 90 | оригинал (молчит) |
| 6 | 0,0 | 3,1 | 0,0 | 0,0 | 90 | оригинал (молчит) |
| 7 | 0,0 | 83,15 | 0,0 | 0,0 | 90 | 90 ✔ |
| 8 | 0,0 | 66,14 | 0,0 | 7,2 | 90 | 90 ✔ |
| 9 | 51,9 | 4,1 | 0,0 | 0,0 | 0 | 0 ✔ |

Итог: 9 из 12 приняты и верны, 0 ошибок, 3 остаются оригиналом (безопасный отказ).
Шесть обычных фото: максимум балла 3, у пяти нули — поворотов 0. Таблица вшита в
тесты как фикстура агрегатов (без фото и имён).

Правило: победитель принимается при **балле ≥15, ≥3 сильных словах (conf >70, len ≥3,
есть буква) и балле ≥2× второго места**. Одно-два случайных слова (3, 5, 9, 10) не
проходят ни по баллу, ни по числу слов; обычные фото дают не более 3. Увеличение 2×
применяется, если длинная сторона < 2000 px.

Fallback RapidOrientation не менялся и срабатывает почти никогда (его уверенность
0,41–0,92, он ошибался): вероятность ≥0.95, отрыв ≥0.80, плюс слабый текст ≥3 слов
на предложенном угле. Если tesseract полностью молчит — оригинал.

Скорость: четыре угла параллельно (по процессу tesseract на угол,
`OMP_THREAD_LIMIT=1`); `--time-limit` (по умолчанию 40 с) ограничивает всё
OCR одного фото: превышение → `status: error`, оригинал не тронут. Реальное время
(ориентир ≤~3 с) в этой копии не измерено — нет tesseract; замер за приёмкой.
Tesseract отсутствует/ошибка → `status: error`, exit 1; `--sheet-only` работает.

Пороги подогнаны под выборку из 12 документов и 6 обычных фото — это эвристика,
не доказанная гарантия; ложные срабатывания на других обычных фото не исключены.

## Что выяснено о пакете

Изучены wheel 0.0.11 с PyPI и исходники автора:

- [Пакет 0.0.11](https://pypi.org/project/rapid-orientation/0.0.11/).
- [Исходники и описание](https://github.com/RapidAI/RapidOrientation).
- ONNX-файл `rapid_orientation/models/rapid_orientation.onnx` лежит в wheel;
  startup открывает локальный файл, не скачивает модель.
- В preprocessing три раза повторяется один центральный crop. Это **не три
  независимых голоса** и не дополнительное свидетельство уверенности.
- Проверка настоящей модели на синтетическом тексте для всех четырёх углов
  подтвердила направление коррекции и структуру вероятностей. Во время этой
  проверки сетевой `socket.connect` запрещён тестом.

## Модель, resume, компакт и деньги

В production wiring модель берётся из config при создании процесса/сессии;
перезапуск перечитывает `.env`. `ClaudeSession._make_options()` передаёт новую
модель вместе со старым `resume`. Проверка ожидаемой модели и output ceiling
уже использует свойства сессии, а не только глобальные EXPECTED-константы.
Дополнительная перепись этих мест не нужна.

Новые тесты моделируют старый Opus cost-state, resume на Sonnet с/без `[1m]`,
assistant model Sonnet, терминальный modelUsage 1000000/128000 с
`canonicalModel` и `costBasis: unknown`. Проверены корректные дельты токенов,
отсутствие ложного invariant latch, обычный/ручной допуск, граница 88% и
сохранение Sonnet при генерации summary и создании новой сессии компакта.
`compact.py` не подставляет свою модель.

**Деньги:** бот не держит таблицу тарифов для Claude и не интерпретирует
`costBasis` / `canonicalModel` для пересчёта цены. Он берёт дельту накопленного
CLI `total_cost_usd`; токены — дельту суммарного per-model modelUsage, включая
вспомогательные модели. Это сохраняется в `response_usage`; `/status` и
`get_bot_status` показывают накопленные в текущем процессе CLI-дельты с четырьмя
десятичными знаками. Если CLI для неизвестного тарифа вернёт ноль или оценку,
бот покажет это число без отдельного маркера unknown. Правильность тарифа
Sonnet при `costBasis: unknown` здесь **не подтверждена**; достоверность цены
зависит от CLI. Тест проверяет сохранение переданного числа, не цену провайдера.
Предупреждение CLI `unrecognized_model` не анализируется ботом как терминальная
ошибка; реальный запрос к Sonnet не выполнялся.

## Экономия на листах

По формуле из задания `width * height / 750`, без claim о точном счёте API:

- 12 исходных фото 1280×720: **14745.6** image tokens.
- Смоук CLI: 3 листа 1568×886, миниатюры 780×439: **5557.0** image tokens.
  Обзор дешевле примерно на **62.3%**.
- Если после обзора открыть ещё `k` исходников, оценка —
  `5557.0 + k * 1228.8`. Выигрыш остаётся при чтении до семи исходников;
  чтение всех двенадцати добавит стоимость обзора. Промпт требует открывать
  только нужные полноразмерные копии, но не экономить на точности реквизитов.
- Для смешанных форматов/квадратов лист может быть 1568×1568: три таких листа
  дают около **9834.5** токена по этой же формуле, экономия обзора ≈33.3%.
- Ограничение длинной стороны 1568 **не равно** ограничению площади ≈1.15 Мп:
  лист 1568×886 содержит ≈1.39 Мп, квадратный — ≈2.46 Мп. Если runtime применит
  ещё и ограничение площади, он дополнительно уменьшит лист и его миниатюры.
  Поэтому читаемость мелких данных по листам не обещается; фактические
  image tokens и ресайз в Claude/Codex здесь не измерялись.

Машиночитаемые агрегаты смоука: `sheet-smoke.json`; проверок и окружения —
`checks.json` и `environment.json`. Исходники смоука полностью
синтетические; временные фотографии и сырые результаты тестов удалены.

## Проверки и ограничения окружения

Использован **предоставленный uv 0.11.28** из broker PATH, CPython 3.12.3,
venv `.venv`. В копии нет `pyproject.toml` и `uv.lock`. Первый требуемый вызов
`uv run --frozen python -m pytest ... -q` завершился
`/usr/bin/python3: No module named pytest`. Затем выполнены `uv venv .venv`
и `uv pip install --python .venv/bin/python -r requirements.txt` с явными
`mcp==1.28.1`, `claude-agent-sdk==0.2.158`, `Pillow==12.3.0`,
`rapid-orientation==0.0.11`, `onnxruntime==1.27.0`, pytest и pytest-asyncio.
Все последующие проверки запускались тем же предоставленным uv через
`uv run --frozen python ...`. **Это не проверка отсутствующего lock**;
остальные зависимости разрешены из requirements, а не сверены с продом.

- Целевой набор (ориентация, листы, смена модели, session limit, usage, reload,
  компакт и admission): **164 passed, 4 skipped**.
- Полный `python -m pytest tests -q`: **collection error**, отсутствует
  `scripts/evaluate_compact_prompt.py`, необходимый `test_compact_evaluator.py`.
- Все доступные тесты с `--ignore=tests/test_compact_evaluator.py`:
  сначала **722 passed, 7 skipped, 2 failed** из-за `AF_UNIX path too long`.
  Длинный префикс каталога копии не помещает pytest tmp_path в sockaddr_un.
- Повтор через `run_available_suite.py`: **724 passed, 7 skipped**.
  Runner оборачивает только tmp_path двух socket-тестов, возвращая относительное
  написание **тех же файлов внутри checkout**. Assert-ы, реальный Unix-сокет,
  stdio MCP-процесс и доставка файла остаются исходными и проходят.
  Замоканных сетевых вызовов вместо этих socket-проверок нет.
- Четыре новых skip — реальные OCR-проверки четырёх поворотов: системный
  Tesseract отсутствует. Остальные три skip — opt-in live Codex и два теста
  отсутствующего spike-артефакта из исходного набора.
- Реальный CLI `--sheet-only`: 12 синтетических входов → 3 листа,
  размер/порядок/соответствие номеров проверены, первый лист осмотрен визуально.
- Реальный CLI без Tesseract: явная ошибка, exit 1, оригинал сохранён.
- `import bot` и `load_system_prompt()` прошли с искусственным токеном,
  без подключения к Telegram. Проверены подстановка шаблона и отсутствие
  зашитых названий моделей в промпте.
