# Codex-рантайм Кеши: решения и найденные дыры

Читать, когда трогаешь `codex_session.py`, `tool_bridge.py`, `file_access.py`, переключение рантайма или формат тулов. Собрано из заметок #15/#16/#20 (31.07–03.08.2026) при пересмотре правил V-48 (17.10.2026). Свежее поведение рантайма — в `README.md`; здесь только то, что дорого узнавать заново.

## Решение и его основание
- **Второй рантайм сделан на подписке Codex, аварийное ручное переключение `/runtime`; автофейловера нет (T8 не делался).** Решение владельца 01.08.2026: ToS-риск принят им. Основание риска: условия OpenAI запрещают программное извлечение вывода («Automatically or programmatically extract data or Output»); в родственных редакциях есть исключение для API, для подписки нет. Мейнтейнер openai/codex: «I'm an engineer, not a lawyer». Вариант с API (без риска) стоил бы сверх подписки.
- **Форк-ветка, а не общий слой.** Общий слой требовал бы обобщить транзакцию компакта (`claude_session`/`compact.py`) и тронуть рабочего Кешу. Поэтому рантаймы разделены протоколом `runtime_protocol.py` (узкий, без компакта) и реестром `runtime_registry.py`, который падает при сборке, если бэкенд врёт о возможностях.
- **Компакт на Codex — родной** (`thread/compact/start`, поток сохраняется): наша транзакция требует владеть сессиями, жжёт квоту на саммари и проверяет текст на мусор, а от Codex текста саммари не получить.
- `codex app-server --stdio` — JSON-RPC, 88 методов (проверено живьём 31.07.2026, спайки #16). Аналоги: `turn/steer` + `thread/inject_items`, `turn/interrupt`, `thread/compact/start`, `thread/resume`, `account/rateLimits/read`. `turn/steer` не используется (#14 заменил инжект очередью; теперь steer есть только у Claude, V-44).
- Единственный архитектурный разрыв был `create_sdk_mcp_server`: тулы внутри процесса бота, а у Codex MCP только внешний stdio → мост по unix-сокету + `kesha_mcp_proxy.py`.

## Дыры моста, найденные в T3 (08.2026), закрыты и проверены атакой
1. **Обход фильтра `chat_id`** пятью написаниями (пробелы, `chat-id`, кириллическая `с`, невидимые символы). Исправление — белый список аргументов из `input_schema` тула + `normalize_arg_name`, не-ASCII отклоняется до нормализации. Чёрные списки проигрышны.
2. **Межчатовая утечка** при двух пользователях: процессная глобаль активного чата перезаписывалась. Адресация идёт через серверную сессию моста (`X-Kesha-Bridge-Session`, случайный истекающий идентификатор) + `copy_context()` на вызов.
3. **Близнецы `send_file`** (`send_photo/video/audio/voice`) принимали произвольный путь: gate на всех пяти и структурный тест, читающий исходник каждого тула с `path`.
4. **TOCTOU**: `FSInputFile` запоминает путь и читает позже, подмена на симлинк после проверки отдавала `.env`. Теперь `open_sendable()` читает в момент проверки (`O_NOFOLLOW`), тулы работают на `BufferedInputFile`. Урок: проверять конечное действие (что ушло в Telegram), а не промежуточную функцию.
5. **Хардлинк** обходил белый список (у ссылки нет «цели»): при `st_nlink>1` все имена обязаны лежать внутри корней.
6. **Утечка с ноутбука легальными командами** (`curl -T`, `ip route flush`, `kill -9 -1`, `find -fprint`): белый список `run_on_laptop` ужесточён; тул остаётся только у Claude.

## Конфигурация Codex
Приватный `CODEX_HOME`, MCP-серверы ровно те, что передал бот (голый app-server наследует глобальные серверы пользователя и выдал бы чату лишние тулы). Секреты MCP не класть в окружение app-server: хуки Codex 0.149 снимают снимок всего родительского окружения; нужен литерал `mcp_servers.<id>.env` в конфиге сессии с правами 0600, а имена этих переменных вычищать из окружения (проверять и shell модели, и generic notify-child). Не печатать argv app-server целиком: в `-c` лежат учётные данные. Боевые rollout'ы Кеши лежат в приватном `codex-home/sessions` каталога сессий, а не в `~/.codex/sessions`.

## Как читать блок «safety» Codex
Текст `This request was blocked by our safety systems` — только поле `message`; в том же кадре app-server лежат `codexErrorInfo` и объяснение guardian'а о том, что сделал ассистент. `_error_chunk` (`codex_session.py`) их не передаёт, поэтому по логам бота причина невидима: воспроизводить своим клиентом и читать сырой кадр (V-37, 08.09.2026; `.orchestra/tasks/V-37/`). Порядок бисекта: убедиться, что «чистая» конфигурация не воспроизводит, затем добавлять отличия прода по одному (cwd → история треда). Помогло: `sol` проходит на той же отравленной истории.
