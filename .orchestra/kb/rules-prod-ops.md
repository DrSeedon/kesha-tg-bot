## Топология и почему так
- **Один прод-узел** (VPS Contabo), сервис `kesha-bot-vps`, код в `/opt/kesha-bot`, CWD бота = каталог заметок (`/opt/cog-second-brain`), пользователь `kesha`. Без фейловера и Redis — решение архитектуры v2.1.
- **Миграция Timeweb → Contabo (#6, 07.2026, простой 90 с, потерь нет).** Причина: 8 GB RAM снимают память как ограничение. Старый российский хост выведен из эксплуатации, данные хранятся как откат.
- **Прокси не нужен.** Прод достаёт Anthropic, Telegram и Deepgram напрямую; прокси выпилен при #6. При переносе `.env` с ноутбука на VPS строки `HTTPS_PROXY` закомментировать: иначе таймауты в несуществующий порт.
- **Xray на 443/8443 того же хоста — VPN владельца, не трогать** (07.2026, #6: при миграции на Contabo Xray встал на тот же хост; сломать его значит отрезать VPN владельца).
- **Деплой делает оркестратор или владелец, не воркер** (решение #24, 03.08.2026). Рестарт бота — тоже не воркер.

## Шпаргалка (хосты — в `/home/kesha/projects/kesha-tg-bot/.orchestra/inventory.local.md`)
Заходить пользователем `kesha`, sudo без пароля (`sudo -n`); root-вход не нужен.
- Деплой (так выкатывались V-42…V-45): `ssh -o BatchMode=yes kesha@<prod> 'cd /opt/kesha-bot && git pull -q --ff-only && .venv/bin/python -c "import bot" && sudo -n systemctl restart kesha-bot-vps'` — только после проверок из AGENTS.md (SHA на remote, `git status` на проде). `--ff-only` и смоук `import bot` до рестарта: сломанный код не рестартует сервис.
- Рестарт: `ssh kesha@<prod> 'sudo -n systemctl restart kesha-bot-vps'`.
- Логи: `ssh kesha@<prod> 'journalctl -q -u kesha-bot-vps --no-pager -n 50'`. Журнал идёт во времени хоста (CEST), строки приложения — по Красноярску (UTC+7), поэтому абсолютный `--since` задавай во времени хоста; относительный (`--since "-30 min"`) работает как обычно.
- Статус: `ssh kesha@<prod> 'systemctl status kesha-bot-vps --no-pager | head -8'`.
- 401 / «Failed to authenticate» = протух вход Claude: под пользователем `kesha` выполнить `claude auth login` (без прокси), открыть ссылку, вставить код, затем рестарт сервиса (`sudo -n systemctl restart kesha-bot-vps`).
- Ручной запуск CLI: `sudo -u kesha -i`, затем `claude`.
- Бэкап БД перед любым деплоем с миграцией: `storage/backup-pre<N>-…db` (принято с #14, 31.07.2026).

Ноутбук держит туннель на прод (порт 2222 только на localhost, пользователь туннеля без shell); ключи вне git.
